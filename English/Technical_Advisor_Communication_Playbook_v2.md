# Technical Advisor Communication Playbook
## English for meetings, leaders, managers, lunch, dinner & social conversations

> Mục tiêu: giao tiếp tự nhiên, ngắn gọn, dễ nói, ít bị vấp khi làm việc với leaders/managers ở Pháp, Singapore và đồng nghiệp quốc tế.

## 1. Nguyên tắc nói để không bị vấp

Ưu tiên câu ngắn. Thay vì nói một câu dài, chia ý:

> I think AI can help a lot.  
> It can reduce manual work.  
> We can deliver more with the same team.  
> Then we can scale it to more projects.

Công thức an toàn: **Point → Reason → Example → Question**

Các câu đệm hữu ích:
- Let me think.
- From my side...
- In our case...
- For me, the key point is...
- The main concern is...
- One example is...
- It depends.
- I need to check.
- I’ll confirm.
- I’ll come back to you.

## 5. AI Transformation / AI Adoption

### Workflow hiện tại
- We already have one common AI workflow for all projects.
- It starts from the story.
- Then we create the spec and plan.
- After that, we move to implementation.
- Then we use AI for code review and QC.
- We also have BA and QC agents.
- Each project has its own knowledge repository.

### Common workflow + separate knowledge
- The workflow is common across projects.
- Each project keeps its own knowledge repository.
- The project knowledge stays separate.
- The common workflow uses project-specific context.
- We should keep the project knowledge accurate and up to date.

> Common workflow, separate knowledge.

### Scale cross-project
- The next step is to scale this to more projects.
- We should make onboarding simple.
- We should avoid too much manual setup.
- If one project finds a better approach, the others should benefit too.
- We should reuse what works.
- We should avoid solving the same problem again and again.

### Productivity
- AI can help us deliver more with the same team.
- We may need fewer extra resources.
- AI can reduce manual work.
- We should measure the real productivity gain.
- We should compare before and after.
- We should check time saved.
- We should also check rework.
- The goal is not only speed.
- We need real value.

### AI cost
- The AI cost can also be high.
- We should compare the productivity gain with the total cost.
- We should look at the total cost, not only the AI cost.
- If AI saves enough engineering time, the higher AI cost may still be worth it.
- Can we compare delivery cost before and after AI adoption?
- How do we measure the cost per story?
- How do we measure the cost per feature?

> More output with the same team is good, but we need to make sure the AI cost is justified.

### Quality
- We should not focus only on speed.
- We also need to check quality.
- We need clear quality gates.
- AI should not stop at code generation.
- We need review, test, and validation.
- The final output still needs human approval.
- We should compare defects before and after AI adoption.
- We should also measure rework.

### Governance & security
- We need common rules.
- We need approved tools.
- We need security rules.
- We need coding standards.
- We need clear review steps.
- What data can we share with AI?
- What data should stay private?
- We need human review for critical changes.

### 30-second contribution
> We already have one common AI workflow for all projects.  
> Each project has its own knowledge repository.  
> Now we should measure the real value.  
> We should check time saved, quality, rework, and AI cost.  
> If the results are good, we can scale it to more projects.

### 60-second contribution
> We already have one common AI workflow for all projects, which is a good starting point.  
> Each project keeps its own knowledge repository, so the workflow can stay common while the context stays project-specific.  
> For me, the next step is to measure the real value.  
> We should check time saved, quality, rework, and AI cost.  
> AI can help us deliver more with the same team, but we need to make sure the cost is still justified.  
> If one project finds a better way of using the workflow, that improvement should benefit the others.  
> Then we can scale with more confidence.

# 21. Mẫu đối thoại qua lại trong công việc

## 21.1. Daily/weekly update với manager

**Manager:** How are things going on your side?  
**You:** Pretty good. We have one issue, but the team is already working on it.  
**Manager:** Is it blocking the release?  
**You:** Not for now. We still have some time.  
**Manager:** Do you need any support?  
**You:** Not yet. Let me check with the team first. If we need help, I’ll let you know.  
**Manager:** Okay, keep me posted.  
**You:** Sure, I will.

### Biến thể
**Manager:** Any major risk this week?  
**You:** The main risk is the deployment timeline.  
**Manager:** Why?  
**You:** We still need to validate one technical point.  
**Manager:** When can you confirm?  
**You:** I should have a clear answer by this afternoon.

## 21.2. Khi manager hỏi mà bạn chưa có câu trả lời

**Manager:** Do we know why this happened?  
**You:** Not yet. I have a few ideas, but I need to confirm first.  
**Manager:** What are you checking?  
**You:** Mainly the logs and the recent changes.  
**Manager:** When can you update us?  
**You:** I’ll come back to you after I speak with the team.

### Cách nói TA hơn
**Manager:** Do you think this is an infrastructure issue?  
**You:** It could be, but I don’t want to jump to a conclusion.  
**Manager:** What do you suggest?  
**You:** Let’s check the application side and infrastructure side in parallel.  
**Manager:** Sounds good.  
**You:** I’ll coordinate with both teams.

## 21.3. Challenge một solution nhưng vẫn lịch sự

**Architect:** I think we should build a new service for this.  
**You:** That could work. I have one concern, though.  
**Architect:** What is it?  
**You:** I’m not sure we need a new service for this use case.  
**Architect:** Why not?  
**You:** We may be able to reuse the existing component. It would be simpler to maintain.  
**Architect:** Do you think it can scale?  
**You:** I think so, but we should validate the load first.  
**Architect:** Okay, let’s check that option.  
**You:** Sure. I’ll prepare a quick comparison.

## 21.4. Khi bạn muốn đưa recommendation

**Manager:** What would you recommend?  
**You:** I would start with the simpler option.  
**Manager:** Why?  
**You:** It has less impact and is easier to roll back.  
**Manager:** What about performance?  
**You:** We should test it, but I don’t expect a major issue.  
**Manager:** Okay.  
**You:** If the test is good, we can move forward with that option.

# 22. AI Transformation – đối thoại thực tế

## 22.1. Nói về workflow AI hiện tại

**Manager:** How do you see the current AI workflow?  
**You:** I think the base is good. We already have one common flow for all projects.  
**Manager:** What should we improve next?  
**You:** For me, the next step is measurement.  
**Manager:** Measurement of what?  
**You:** Time saved, quality, rework, and AI cost.  
**Manager:** Which one is the most important?  
**You:** I would start with time saved and rework. They are easier to compare.  
**Manager:** Makes sense.  
**You:** Then we can add cost and quality metrics.

## 22.2. Nói về AI productivity

**Leader:** Do you think AI is really improving productivity?  
**You:** Yes, but we need to measure it carefully.  
**Leader:** What do you mean?  
**You:** AI can help us deliver more with the same team, but it can also create rework if the output is not good.  
**Leader:** So how should we measure it?  
**You:** I would compare the time before and after AI adoption for the same type of task.  
**Leader:** Anything else?  
**You:** Yes, we should also track review findings and defects.

## 22.3. Nói về AI cost

**Manager:** The AI cost is getting high. Is it still worth it?  
**You:** It depends on how much engineering time we save.  
**Manager:** How can we prove that?  
**You:** We can compare the delivery cost before and after AI adoption.  
**Manager:** Per project?  
**You:** I would start per story or per feature. It’s easier to compare.  
**Manager:** Good idea.  
**You:** Then we can see where AI gives the best return.

## 22.4. Scale từ 5 projects sang nhiều projects hơn

**Leader:** We have five projects using the workflow now. What should we do next?  
**You:** I think we should learn from these five before scaling too fast.  
**Leader:** What should we look at?  
**You:** Which steps work well, where teams still need manual work, and where AI creates rework.  
**Leader:** And after that?  
**You:** We can simplify onboarding and roll it out to more projects.  
**Leader:** Do we need a different workflow for each project?  
**You:** No. The workflow can stay common. The project knowledge stays separate.

## 22.5. Knowledge repo riêng cho từng project

**Manager:** Why do we need a separate knowledge repository for each project?  
**You:** Because each project has different business rules, architecture, and coding standards.  
**Manager:** Does that make maintenance harder?  
**You:** A little, but it keeps the context clean.  
**Manager:** How do we avoid outdated knowledge?  
**You:** We need clear ownership and regular updates.  
**Manager:** Who should own it?  
**You:** Ideally, the project team owns the content, and we define common guidance at TA level.

## 22.6. AI quality và human review

**Leader:** Can we trust AI output enough to reduce manual review?  
**You:** For low-risk tasks, maybe.  
**Leader:** What about production code?  
**You:** I would still keep human review.  
**Leader:** Even if the AI agent already did a code review?  
**You:** Yes. AI can help us find issues, but the final decision should stay with the team.  
**Leader:** So AI is more like an assistant?  
**You:** Exactly. It helps us move faster, but it should not remove accountability.

# 23. Cross-project technical discussion

## 23.1. Khi một project muốn làm riêng

**Project Lead:** Our project is a bit different. We want our own solution.  
**You:** I understand. What is the main difference?  
**Project Lead:** We have a different architecture.  
**You:** That makes sense. But maybe we can still reuse the common pattern.  
**Project Lead:** Which part?  
**You:** The workflow and governance can stay common. Only the project-specific implementation needs to change.  
**Project Lead:** That could work.  
**You:** Let’s identify what is really unique first.

## 23.2. Khi phát hiện duplicate work giữa projects

**You:** I noticed two teams are solving a very similar problem.  
**Manager:** Which teams?  
**You:** Project A and Project B.  
**Manager:** Are they using the same approach?  
**You:** Not exactly. That’s why I think we should compare them.  
**Manager:** What do you suggest?  
**You:** Let’s see if we can create one reusable pattern instead of maintaining two solutions.  
**Manager:** Good point.  
**You:** It could save time for future projects too.

# 30. Khi conversation bị dead

Nếu người kia trả lời ngắn, dùng:
- Really? Why?
- How was it?
- Which one?
- How often?
- What happened?
- What about you?
- Do you prefer that?
- Was it difficult?
- Did you enjoy it?
- Would you do it again?

### Ví dụ

**Manager:** Sometimes.  
**You:** Which country do you visit most often?  
**Manager:** Singapore.  
**You:** Do you enjoy working there?

**You:** What do you like most about it?

# 31. Cách kể một câu chuyện ngắn

# 37. Công thức luyện hội thoại

Mỗi chủ đề luyện 4 bước:
1. **Open** — hỏi câu đầu.
2. **React** — phản hồi ngắn.
3. **Follow up** — hỏi thêm.
4. **Share** — kể một chút về mình.

### Ví dụ
**Open:** Have you been to Singapore before?  
**React:** Nice.  
**Follow up:** Which area did you stay in?  
**Share:** I like the food there. There’s a lot of variety.

Đây là cách tránh kiểu hội thoại giống phỏng vấn: không chỉ hỏi liên tục mà còn chia sẻ một chút về bản thân.

## 20. Cách luyện hằng ngày

Mỗi ngày 15–20 phút:
1. Chọn 10 câu.
2. Đọc chậm 3 lần.
3. Đọc nhanh 3 lần.
4. Ghép thành một đoạn 30–60 giây.
5. Tự trả lời 3 câu hỏi follow-up.
6. Lặp lại đến khi không cần dịch từ tiếng Việt trong đầu.

Ưu tiên:
- câu ngắn,
- từ quen,
- nhịp rõ,
- nói chậm hơn 10–15% so với bình thường.

Mục tiêu không phải nói như native speaker.  
Mục tiêu là: **clear, calm, confident, easy to follow.**
