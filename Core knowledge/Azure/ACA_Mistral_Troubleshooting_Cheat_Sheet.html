Azure Container Apps + Mistral Workflow Troubleshooting Cheat Sheet

Mục tiêu: tài liệu tham khảo nhanh cho case `maia-wf-worker` chạy trên Azure Container Apps (ACA), dùng User Assigned Managed Identity, Azure Container Registry, Key Vault references và Mistral Workflows.

>

Resource mẫu:

>

- Resource Group: `rg-weu-azu-aidlc-sb`
- Container App: `maia-wf-worker`
- Managed Identity: `maia-wf-identity`
- Key Vault: `kv-maia-wf`
- ACR: `acrmaiawf.azurecr.io`

>

**Quy tắc:** không in secret value ra console/log production.

1. Set biến dùng chung

$rg  = "rg-weu-azu-aidlc-sb"
$app = "maia-wf-worker"
$kv  = "kv-maia-wf"
$mi  = "maia-wf-identity"

3. Kiểm tra Microsoft.App provider

Check registration state

az provider show `
  --namespace Microsoft.App `
  --query "registrationState" `
  -o tsv

Expected

Registered

Nếu:

NotRegistered

thì register:

az provider register `
  --namespace Microsoft.App `
  --wait
Nếu bị `AuthorizationFailed`, thường cần quyền ở **subscription scope**, không chỉ Contributor trên Resource Group.

9. Update env var - tạo revision mới

Ví dụ sửa Mistral endpoint:

az containerapp update `
  -n $app `
  -g $rg `
  --set-env-vars "SERVER_URL=https://api.maia.dc.mistral.ai"

Expected behavior

ACA tạo revision mới, ví dụ:

maia-wf-worker--0000008
        ↓ update env
maia-wf-worker--0000009

Verify

az containerapp revision list `
  --name $app `
  --resource-group $rg `
  --query "[].{
    Revision:name,
    Active:properties.active,
    RunningState:properties.runningState,
    HealthState:properties.healthState
  }" `
  -o table

Expected output

Revision                  Active    RunningState    HealthState
------------------------  --------  --------------  -----------
maia-wf-worker--0000008   True      Running         Healthy
maia-wf-worker--0000009   True      Running         Healthy
Nếu mode là `Multiple`, nhiều revision có thể Active cùng lúc.

az containerapp revision list `
  --name $app `
  --resource-group $rg `
  --query "[].{
    Revision:name,
    Active:properties.active,

Example output

------------------------  --------  --------------  -----------
maia-wf-worker--0000005   True      Running         Healthy

Cách đọc

Active=True + Running + Healthy → revision đang ổn
Activating + None               → chưa nên deactivate revision cũ

12. Find active revision

$revision = az containerapp revision list `
  --name $app `
  --resource-group $rg `
  --query "[?properties.active==``true``].name | [-1]" `
  -o tsv

Write-Host "Active revision: $revision"

Expected

Active revision: maia-wf-worker--0000009
Với multiple revision mode, `[-1]` chỉ chọn một active revision theo output order. Nếu cần chính xác revision mới nhất, kiểm tra list trước.

23. Troubleshoot `401 Wrong API endpoint`

Symptom

Status 401
Body: {"detail":"Wrong API endpoint"}

Check config loaded

Trong startup log:

'worker': {
  'server_url': 'https://api.eu.mistral.ai'
}

Nếu expected endpoint là:

https://api.maia.dc.mistral.ai

thì update:

az containerapp update `
  -n $app `
  -g $rg `
  --set-env-vars "SERVER_URL=https://api.maia.dc.mistral.ai"

Sau đó revision mới phải log:

'server_url': 'https://api.maia.dc.mistral.ai'

và diagnostic:

[OK] Mistral API (...): HTTP 200

24. `SERVER_URL` vs `MISTRAL_API_URL`

Observed env example:

SERVER_URL       https://api.eu.mistral.ai
MISTRAL_API_URL  https://api.mistral.ai

Nhưng config loaded:

worker.server_url = https://api.eu.mistral.ai

=> SDK đang dùng:

SERVER_URL

cho worker endpoint.

Nếu MISTRAL_API_URL không được application dùng, nên remove để tránh confusion:

az containerapp update `
  -n $app `
  -g $rg `
  --remove-env-vars MISTRAL_API_URL

25. Check Key Vault secret metadata - không print value

$names = @(
  "mistral-api-key",
  "azure-devops-org-url",
  "azure-tenant-id",
  "azure-client-id",
  "azure-client-secret"

foreach ($name in $names) {
  az keyvault secret show `
    --vault-name $kv `
    --name $name `
    --query "{
      name:name,
      enabled:attributes.enabled,
      updated:attributes.updated,
      expires:attributes.expires,
      id:id
    }" `
    -o jsonc
}

Example

{
  "enabled": true,
  "expires": null,
  "id": "https://kv-maia-wf.vault.azure.net/secrets/azure-client-id/<version>",
  "name": "azure-client-id",
  "updated": "2026-08-28T..."

Không dùng `--query value` cho secret nhạy cảm trong shared console/log.

26. Update Key Vault secret

Nếu bạn có Key Vault Secrets Officer:

az keyvault secret set `
  --vault-name $kv `
  --name "<secret-name>" `
  --value "<secret-value>"

Expected

Azure trả secret metadata JSON.

Production-safe pattern

Không hard-code secret vào script:

az keyvault secret set `
  --vault-name $kv `
  --name "azure-client-secret" `
  --value "$(azure-client-secret)"

với pipeline variable được mark secret.

27. Key Vault RBAC

Runtime ACA chỉ cần đọc secret:

Key Vault Secrets User

Pipeline cần create/update secret:

Key Vault Secrets Officer

Recommended split:

Deployment identity → Key Vault Secrets Officer
Runtime identity    → Key Vault Secrets User

30. Investigation flow nhanh

1. Correct subscription?
   ↓
2. Microsoft.App registered?
   ↓
3. ACA state = Succeeded?
   ↓
4. Managed Identity attached?
   ↓
5. ACR configured + AcrPull?
   ↓
6. Key Vault references exist?
   ↓
7. Container env points to secretRef?
   ↓
8. Revision Running/Healthy?
   ↓
9. System log: image pull/start OK?
   ↓
10. Console log: app error?
   ↓
11. Exec shell
   ↓
12. Run Mistral diagnose
   ↓
13. WHOAMI HTTP 200?
   ↓
14. Temporal connectivity OK?

31. Production notes

• Không in `MISTRAL_API_KEY`, `AZURE_CLIENT_SECRET` hoặc secret values vào logs.

• `az containerapp update --set-env-vars` và `--remove-env-vars` tạo revision mới.

• Với `Multiple` revision mode, update không có nghĩa revision cũ tự biến mất.

• Chỉ deactivate revision cũ sau khi revision mới `Running + Healthy`.

• `PulledImage` thành công chứng minh ACR access đã qua.

• Container exit code `1` thường là application-level failure, không phải provisioning failure.

• `WHOAMI HTTP 200` là evidence mạnh cho endpoint/API key.

• `Temporal [OK]` là evidence scheduler connectivity.

• Runtime identity nên dùng least privilege (`Key Vault Secrets User` thay vì Officer nếu chỉ đọc).

• Không dùng `Key Vault Secrets Officer` cho runtime nếu không cần ghi secret.

• Không expose secret value trong Classic Release inline script.
